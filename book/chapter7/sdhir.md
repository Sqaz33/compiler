# SDHIR

## 1. Определение

**SDHIR** (*Selection DAG HIR*, или HIR на Selection DAGs) — это промежуточное представление между **HIR** и **LIR**, в котором HIR-программа представляется не как обычная функция с базовыми блоками, `PHI`-узлами, переходами и циклами, а как набор ациклических подпрограмм, каждая из которых является **Selection DAG**.

Selection DAG в составе SDHIR — это вырезанный из HIR ациклический подграф вычислений, пригодный для последующего выбора инструкций. Внутри каждого Selection DAG сохраняется SSA-представление: значения по-прежнему определяются один раз и используются через связи по данным.

Значения, которые должны передаваться между разными DAG, выносятся во внешние виртуальные регистры, например `r0`, `r1`, `r2`. Для записи результата во внешний виртуальный регистр используется стрелка `<-`, например `r0 <- widen.2`. Такая запись нужна для сшивания отдельных DAG между собой.

Главное отличие от HIR состоит в том, что **HIR** описывает функцию через общий граф управления с базовыми блоками, циклами, переходами и `PHI`-узлами, а **SDHIR** заменяет участки HIR на ациклические Selection DAG и связывает их через виртуальные регистры и переходы вида `exec DAG1`, `exec DAG2`.

SDHIR ещё не является LIR и не является машинным кодом. Это подготовительное представление, которое упрощает задачу выбора инструкций: выбор выполняется не сразу для всей функции с циклами и обратными дугами, а для отдельных ациклических подграфов.

Кратко: **SDHIR — это HIR, разрезанный на ациклические Selection DAG, где внутренняя часть каждого DAG остаётся в SSA-стиле, а связь между DAG выполняется через виртуальные регистры и переходы `exec DAG`**.

## 2. Краткие шаги перехода HIR-функции к SDHIR-функции

1. Берётся HIR-функция с базовыми блоками, SSA-значениями, `PHI`-узлами, переходами и циклами.

2. Функция разбивается на ациклические подграфы. В простом случае можно построить один Selection DAG для каждого базового блока.

3. Каждый ациклический участок оформляется как отдельная подпрограмма вида `DAG1`, `DAG2`, `DAG3`.

4. Внешние входные значения, которые приходят в DAG извне, заменяются чтением из виртуальных регистров: например `widen.1 = r0`, `x.1 = r1`, `sum.0 = r2`.

5. `PHI`-узлы устраняются внутри DAG: вместо выбора значения через `PHI` используются значения, уже переданные через виртуальные регистры.

6. Вычисления внутри DAG оставляются в SSA-стиле: например `t0 = *x.1`, `t1 = t0 & 1`, `sum.1 = sum.0 + t2`.

7. Значения, которые должны быть доступны после выполнения DAG, записываются обратно во внешние виртуальные регистры: например `r0 <- widen.2`, `r1 <- x.2`, `r2 <- sum.1`.

8. Переходы между базовыми блоками заменяются переходами между DAG: например вместо `goto BB2` используется `exec DAG2`.
